# Metadata Update Mechanism

## Problem

When switching between organizations, the document title and favicon weren't updating correctly. This was because:

1. Next.js caches the metadata generated by `generateMetadata()` in the root layout
2. Multiple components were trying to set metadata in different ways
3. No consistent client-side update mechanism existed for when users switch organizations

## Solution

### 1. Server-side Initial Metadata

- `src/lib/services/pageMetaData.ts` provides the initial metadata for server-side rendering
- This is used by `generateMetadata()` in the root layout
- This sets the initial page title and favicon when the app first loads

### 2. Client-side Dynamic Updates

- `src/app/client-layout.tsx` now handles dynamic metadata updates
- It uses `useEffect` to update the document title and favicon when:
  - The user logs in
  - The user switches organizations
  - Portal settings change

### 3. Implementation Details

- We removed redundant metadata setting from various components
- We consolidated the logic in `client-layout.tsx`
- We ensure both standard favicon and apple-touch-icon are updated
- We handle error cases by falling back to default values

### 4. Testing

To test that the metadata updates correctly:

1. Log in to the first organization
2. Verify the title and favicon match that organization
3. Switch to another organization
4. Verify the title and favicon update to match the new organization

If you need to make further changes to the metadata update mechanism, focus on modifying the `useEffect` in `client-layout.tsx`.
